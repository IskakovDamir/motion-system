# Building primitives (step 7)

How a primitive is written, so every group reads the same. The catalogue (`analysis/catalogue.json`)
decides which primitives exist, their variants and which techniques each variant carries; the
measurements (`timeline.md` rows, printed per technique by `scripts/analysis/techniques.py show <id>`, and
`curves/<id>.json`) give every number.

## Files

`src/motion/primitives/<group>/<Name>.spec.ts` and `<Name>.tsx`, nothing else outside your group.
Helpers only your group uses go in the same folder under any name that does not end in `.spec.ts`.
Do not edit `src/motion/engine/`, `src/motion/tokens/`, other groups, `specs.ts` or `index.ts` (the
registry is regenerated by `scripts/gen_registry.py` once every group is in). If something shared is
missing, write it inside your group and say so when you return.

## The spec: data only

```ts
import type {PrimitiveSpec} from '../types';
import {EASE, motion} from '../../tokens/easing';
import {measured} from '../../tokens/measured';

export const spec: PrimitiveSpec = {
	name: 'CardSlideIn',               // the catalogue name
	kind: 'ui',                         // the catalogue kind
	description: 'A card enters from the side: a short slide with a fade, ease-out; more cards follow on a fixed stagger.',
	defaultVariant: 'short',            // the catalogue default_variant
	variants: {
		short: {
			// v1.card-slide-fade-in: first visible at +8.6% W, 13-14 f ease-out; the second card starts 3 f later
			motions: {x: measured('v1.card-slide-fade-in'), opacity: motion(13, EASE.outStrong)},
			params: {fromX: 8.6, stagger: 3},
			reproduces: {x: ['v1.card-slide-fade-in']},   // the variant's curve technique, under the property it drives
			covers: ['v3.card-slide-in-left'],             // the variant's other techniques (no curve of their own)
		},
	},
	demoFrames: 90,                     // frames the isolated demo needs (60 fps)
	demoTone: 'light',
};
```

- Variant names are exactly the catalogue's. Every technique the catalogue puts in a variant appears
  once in it: the curve technique in `reproduces[<property>]`, the others in `covers`.
- The curve technique's property uses `measured('<curve id>')` unchanged (add a delay with
  `measured(id, delay)` if that move starts later inside the variant). That motion is what verify.py
  samples, and the component must animate that property with exactly that progress.
- Every other motion is `motion(<frames>, EASE.<token>, <delay>)` with the frames measured in
  timeline's movement rows and the EASE token whose shape is closest to the measured fit (read
  the shape notes in `easing.ts`; `measured.ts` shows which token each curve of that family got).
- `params` hold the measured amplitudes and counts: travel in % of frame width or height, scale
  factors, degrees, opacity, blur (% of frame width), px at 1080p, staggers and holds in frames,
  step lists. Put a short comment naming the technique a number comes from when it is not obvious.
  No number in a spec is invented: if the measurements do not give it, the variant does without that
  feature and you report it.
- Specs import only types and tokens (no React, no fonts), so plain Node can read them.

## The component: reads the spec

```tsx
import type React from 'react';
import {mix, num, useFrame, useProgress, variantOf} from '../../engine/anim';
import {scheme, type Tone} from '../../tokens/colors';
import {spec} from './CardSlideIn.spec';

export type CardSlideInProps = {variant?: string; tone?: Tone; children: React.ReactNode[]};

export const CardSlideIn: React.FC<CardSlideInProps> = ({variant, children}) => {
	const v = variantOf(spec, variant);
	const p = useProgress(spec, variant);     // p(prop, offsetFrames) -> progress at this frame
	const {w} = useFrame();                   // w(% of width) / h(% of height) / px(px at 1080) -> px
	return (
		<>
			{children.map((child, i) => {
				const off = i * num(v, 'stagger');
				return (
					<div key={i} style={{transform: `translateX(${w(mix(p('x', off), num(v, 'fromX'), 0))}px)`, opacity: p('opacity', off)}}>
						{child}
					</div>
				);
			})}
		</>
	);
};
```

- `<Name>` is the reusable component: content comes in as props (text, items, children, footage,
  tone); timing and measured geometry come from the variant. No timing or geometry literal in it.
- Colours only through `scheme(tone)` roles; type through `FONT`, `TYPE`, `fontSize(role, height)`
  and `REVEAL` (`tokens/type.ts`); text units through `splitText` (`engine/text.ts`); motion blur
  through `DirectionalBlur` (`engine/blur.tsx`).
- Footage only through `FootageSlot` (`../footage/FootageSlot`, props fixed): the card, window or
  mask around it owns the motion.
- A transition that overlaps two compositions (push, whip, zoom-through, dissolve, wipe ...) also
  exports a TransitionSeries presentation (`<name>Presentation(variant?)`, built on
  `TransitionPresentation` from `@remotion/transitions`) and its timing via `motionTiming(motion)`
  (`engine/transition.ts`), so a new edit can use it between any two scenes.
- A measured curve that is the envelope of a stepped or pulsed move (a zoom in 12 quick steps, a
  blink) is used as the envelope; the component quantises it into the measured steps (params).
- 3D: `@remotion/three` (`ThreeCanvas`) with three.js geometry and materials made in code. No
  model or texture files.
- Deterministic: no `Math.random`, `Date` or CSS transitions/animations; use `random(seed)` from
  remotion and frame-driven values only.

## The Demo: neutral content

`export const Demo: React.FC<DemoProps>` shows one variant (`variant` prop) alone on a 1920x1080
frame, starting at its frame 0 and holding the settled state to the end of `demoFrames`. Content is
new and neutral: short plain words (not the references' words, not brand names), numbers, simple
geometric icons drawn in SVG, gray FootageSlot plates for footage. No person, face, hand or
silhouette, no logos, nothing laid out like a reference frame. Positions and sizes that are measured
come from the variant params; free layout of the demo content is yours.

## Checks (run until clean, and look at every picture)

```
.venv/bin/python scripts/check_group.py <group>      # catalogue mapping, curve timing (verify rule), tsc in your files
.venv/bin/python scripts/probe_group.py <group> [--only Name] [--frames A B]
    # renders each variant alone -> .tmp/probe/<group>/sheets/*.jpg (tiles: p = probe frame, m = motion frame)
.venv/bin/python scripts/compare_sheets.py --group <group> [--only <technique> ...]
    # reference moments (left) next to the same phase of your variant (right), plus the measured vs
    # built curve -> .tmp/probe/<group>/compare/<technique>/sheet.jpg
```

Open every sheet with the Read tool. Compare phase by phase: where each element starts and ends (%
of frame), scale, rotation, opacity, blur, what moves first and what follows, how fast it settles.
Reference frames show the motion to reproduce, never content to copy. Fix what differs and check
again.
